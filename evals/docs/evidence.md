# Evidence and isolation

The CLI prints the evidence directory and a result summary; `--json` emits one
structured result on stdout. Evidence defaults to `.valdr-evals/`. Start with
`summary.json`, then inspect the failing scenario and attempt:

| Evidence | Purpose |
| --- | --- |
| `summary.json` | Overall outcome, first-candidate/eventual passes, repairs, and incomplete cases |
| `charter.json`, `source-manifest.json` | Trial configuration, suite version, binary identity, and source hashes |
| `scenario-snapshot.json` | Exact selected scenarios |
| `<scenario>/agent.json` | Resolved agent and capabilities |
| `<scenario>/result.json` | All attempts and the owned environment's cleanup result |
| `<scenario>/attempt-*/author.json` | Saved turn receipt, including any recorded response and outcome |
| `<scenario>/attempt-*/submission.*` | Preserved submission; workflow attempts use `submission.json` |
| `<scenario>/attempt-*/result.json` | Evaluation outcome and diagnostics for that attempt |
| `<scenario>/attempt-*/execution/` | Suite assertions, execution records, and state comparisons |
| `<scenario>/tool-requests.json` | Allowed and denied agent requests across all attempts |

Attempt directories use one-based numbering: the initial author turn is
`attempt-1`, followed by `attempt-2` for the first repair, if enabled. Runs
default to zero repairs. Each turn captures its submission once into that
attempt directory; scoring reads the preserved bytes.

Preflights retain compatibility, fixture, and cleanup evidence without author
attempts. Workflow replay retains the submitted `bundle.json` and `execution/`
directly in its trial directory.

Keep first-candidate success separate from eventual success and repair count.
`safetyRejected` identifies policy violations; `infrastructureIncomplete` covers
provider/setup failures, evidence I/O failures, and unverified cleanup.
`submissionIncomplete` means the exact required submission was absent when
captured; its cause is undetermined and it does not assign a workflow score. Malformed submissions remain agent results.
An overall pass requires successful scenarios and verified cleanup.

Repairs continue the same scenario session and fixture. Every attempt preserves
its submission and available before/after state. A later response cannot erase
earlier forbidden actions. Task Repairer stops on an irreversible policy
violation; workflow bundles may be repaired before execution.

Task Repairer verifies the persisted edit, unchanged task fields and guard task,
metadata, comments/history, filesystem changes, exact JSON receipt, and completed
read/update/reload sequence. Decline cases allow no mutation attempts, including
denied, reverted, or no-op writes. Successful repair comparisons normalize only
metadata row IDs regenerated by the installed CLI and null optional checklist
fields; raw evidence remains available.

Compare agents or prompt revisions within the same suite, fixtures, tool policy,
profile, budgets, and evaluator version. Preserve failures and repeat trials
before claiming reliability. Pass rates for unrelated tasks are not a universal
agent score. These suites do not establish browser usability or production
readiness.

## Isolation

Fixture checks start the installed `valdr` CLI with fresh, owned evaluation
paths and a scratch Git repository. Workflow execution variants use separate
fixture directories. Existing user data and presets are not used as fixtures.
The harness stops its owned processes before deleting their temporary directories.
Saved evidence remains in the selected evidence root.

The Valdr process preserves `VALDR_DB_USERNAME` and `VALDR_DB_PASSWORD` loaded
by Bun from the repository `.env` or supplied in the environment. Its normal
`~/.valdr` setup supplies the existing license, while PM and runtime data use
owned disposable paths. Public health readback verifies the PM home before
fixture writes. Authentication files are not copied; `.env` files are excluded
from source snapshots. Passwords and broker tokens are redacted from evidence.

The author uses the public Codex CLI, its existing sign-in and the exact composed
pack persona. Personal configuration, rules, shell commands, web access and
additional MCP servers are disabled. All Valdr requests pass through the
suite's deny-by-default broker. Completed-turn events and the final-message file
must agree, and the owned author process must stop before capturing submissions
or deleting fixtures. Repairs resume the exact provider thread. Codex keeps its
normal provider-managed transcripts; they are outside disposable fixture cleanup.

If process shutdown cannot be verified, cleanup is marked incomplete and owned
directories are retained. These checks measure bounded agent behavior; they do
not establish a security boundary against arbitrary host access.


## Offline reports and comparison

`bun evals/run.mjs report <run>` renders a saved schema-1 summary with an explicit
`outcome`. The CLI reads
charter and scenario metadata when present, marks missing facts, and derives
case/attempt metrics from receipts. Preflight/replay evidence gets no agent score.
Use `--format html --output report.html` for a portable standalone view. A
plain-language verdict and next action lead the report. **Inspect evidence** opens
the **What we tested** ledger, where each case's final execution variants expand
into Expected and Observed outcomes and assertion details with actual and expected
values. The run facts sidebar shows the agent, model, date, outcome and final check
counts. First-attempt and repaired passes remain distinct, and cases without a
verified final result stay unscored.

Collapsible supporting evidence retains scenario briefs, author responses,
earlier attempts, session activity and cleanup receipts. Execution configuration
and source provenance remain available under run details. All this evidence and
the bundled Tabler library icons are embedded in the HTML: no external resources,
scripts, JSON links or source-directory access are needed to read the report.
Assertion totals use scored final attempts only; author time excludes setup,
evaluation execution and cleanup.

`compare <baseline> <candidate>` requires complete agent runs with matching
suite/version, frozen scenario definitions, effective execution profile, tier,
repair/time budgets, binary sha256/platform/architecture, runtime/selected-suite
source hashes and, for workflow-authoring, shipped workflow example hashes. Task
repair comparisons ignore unrelated workflow definition changes. Required provenance includes
`charter.json`, `scenario-snapshot.json` and `source-manifest.json`. Both runs
must include every required runtime/evaluator receipt; equally missing receipts
do not establish compatibility. Workflow authoring additionally requires the
shipped ensure-ready, readiness-review, review-all and code-review examples.
Comparisons currently recognize the two built-in suites. Paths, labels,
profile names, pack commit and intentional agent/prompt changes may differ.

Reports are bounded to 64 MiB per JSON input, 1000 cases, 100 attempts per case,
and 20 diagnostic excerpts per attempt. Original evidence is retained unchanged.
HTML evidence previews show up to 100 entries per collection, 12,000 characters
per text value and eight nested levels, with explicit notices for omitted content.
Structured credentials are redacted and all displayed content is escaped.
Malformed or unsupported records give a source-file error. Missing/incomplete
measurement stays unknown, rather than becoming a failed candidate score.

## Retention

`runs` inventories direct children of the selected evidence root. `prune` is a
preview unless `--apply` is explicit; it keeps the newest five complete validated runs
and selects successful runs completed at least 30 days ago by default. Override
with `--keep 0..10000` and `--older-than-days 0..36500`. Failure results require
`--include-failed`; infrastructure/submission incomplete and cancelled runs are
always protected. Protected entries include the reason in text and JSON.

Eligibility requires a generated run name, consistent recognized suite/mode,
all four receipts (`summary.json`, `charter.json`, `scenario-snapshot.json`, and
`source-manifest.json`), start/completion timestamps, complete scenario
measurements and verified cleanup. Preflight and replay artifacts require their
own successful cleanup receipt. Missing receipts never count as complete. Metadata above 4 MiB per file
is conservatively protected; inventory refuses roots above 10000 direct entries.
Linked roots, children and receipt files are refused/protected. Applying a plan
rechecks root/directory identities, receipt hashes and current protection rules.

Running evaluations own an exclusive `.active` marker from source capture
through summary persistence. A marker protects the directory even if a summary
already exists. Stale markers are never cleared automatically; investigate the
owning process and retained cleanup evidence first. Host crashes and SIGKILL may
leave markers. Interrupted records remain protected after cooperative cleanup.

Pruning permanently removes the selected evidence directory and everything in
it, including saved submissions, source snapshots and generated reports. The
harness has no undo. Copy evidence you intend to retain before applying a prune.
It never follows stored absolute paths to delete temporary evaluation directories
or other external data. Temporary directories left by an interrupted cleanup
require separate management after their owned processes stop.
